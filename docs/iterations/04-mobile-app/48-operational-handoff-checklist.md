# Iteration 04 - Operational Handoff Checklist

## Handoff Goal
Transfer core mobile MVP flow to realtime integration and beta hardening.

## Owners To Hand Off
- Flutter feature owner.
- Generated client owner.
- MobX store owner.
- UI state owner.
- Product UX owner.

## Assets To Hand Off
- Feature-slice structure.
- DTO-to-domain mapper tests.
- Store state tests.
- Core flow screenshots or golden states.
- Error/offline/stale state notes.

## Known Issues
- Advanced polish can be deferred.
- Deep offline-first behavior can be phased later.
- Non-critical settings may wait for beta feedback.

## Support Impact
- Support should know user-visible error states.
- Product should know onboarding and core-loop friction points.

## Acceptance
Iteration 05 owner accepts handoff only when realtime can integrate through feature stores without bypassing mobile architecture.
