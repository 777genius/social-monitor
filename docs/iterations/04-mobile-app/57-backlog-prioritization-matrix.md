# Iteration 04 - Backlog Prioritization Matrix

## Prioritization Goal
Complete the user-visible MVP loop before polish and secondary settings.

## P0 - Do First
- Flutter shell.
- Generated client wrapper.
- DTO-to-domain mapping.
- Topic feature.
- Source binding feature.
- Feed and summary feature.

## P1 - Do After P0
- Store tests.
- UI states: loading, empty, error, stale and offline.
- Citation drill-down.
- Error mapping.
- Required headless component integration.

## P2 - Defer If Needed
- Advanced visual polish.
- Deep offline-first behavior.
- Non-critical settings.
- Secondary analytics screens.

## Prioritize Higher When
- Work affects core loop completion.
- Work affects failure visibility.
- Work affects domain/DTO boundaries.
- Work affects realtime readiness.

## Do Not Prioritize
- Polishing before core loop works.
- Widgets before feature boundaries.
- Realtime prep before stable store states.
