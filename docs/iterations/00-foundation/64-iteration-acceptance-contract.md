# Iteration 00 - Iteration Acceptance Contract

## Provider
Foundation team provides product, architecture, source-policy and contract decisions.

## Receiver
Iteration 01 platform team receives decisions required to scaffold the backend and contracts.

## Handoff Promises
- Product loop is clear enough to map to backend modules.
- Glossary terms are stable enough for code and API naming.
- Bounded contexts have owners.
- Source acquisition policy has risk classes.
- REST/event standards include tenant scope, versioning and idempotency.

## Receiver Expectations
- Platform team can create scaffold tickets without redefining product vocabulary.
- Contract owner can generate first API examples from standards.
- Source policy can block unsafe connector planning.

## Blocking Defects
- Missing context owner.
- Unclassified source strategy.
- Contract standard without implementation example.

## Allowed Exceptions
- Future source priority ranking can remain open.
- Provider-specific operational limits can move to ingestion work.
