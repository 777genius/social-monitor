# Iteration 07 - Master Implementation Sequence

## PR Slice Rule
- One PR should change one launch slice: scope freeze, limitations, onboarding, rollback, feedback taxonomy or roadmap synthesis.
- Each PR must improve launch safety, support clarity or evidence quality.
- Split if beta feedback processing is bundled with new feature/source implementation.

## Step 1 - Open Control Docs
- Read beta scope, launch readiness and final go/no-go docs.
- Confirm product, engineering, support, operations and source policy owners.
- Check rollback, known-limitation and onboarding blockers.

## Step 2 - Cut Tickets
- Create beta scope freeze ticket.
- Create known limitations ticket.
- Create onboarding walkthrough ticket.
- Create launch/rollback checklist ticket.
- Create feedback taxonomy ticket.
- Create post-MVP roadmap synthesis ticket.

## Step 3 - Execute In Order
- Freeze scope before onboarding.
- Publish known limitations before launch.
- Validate rollback before inviting beta users.
- Classify feedback before roadmap decisions.

## Step 4 - Validate
- Run onboarding walkthrough.
- Review launch and rollback evidence.
- Review metrics and feedback taxonomy.
- Confirm unsupported sources remain out of active scope.

## Step 5 - Close
- Fill final go/no-go.
- Handoff prioritized post-MVP backlog, ADRs and quality-gate updates.
- Promote only when beta evidence validates the core loop and next roadmap.
