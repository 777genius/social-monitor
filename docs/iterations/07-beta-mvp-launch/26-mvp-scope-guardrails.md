# Iteration 07 - MVP Scope Guardrails

## In Scope

1. Scope freeze.
2. Supported source list.
3. Onboarding.
4. Launch checklist.
5. Support runbook.
6. Feedback taxonomy.
7. Beta metrics.
8. Source expansion decision process.

## Out Of Scope

1. Broad public launch.
2. Adding new source adapters during launch.
3. Enterprise onboarding automation.
4. Large-scale growth experiments.

## Scope Creep Signals

- Beta feedback is used to add features before stabilizing core loop.
- Unsupported source becomes launch blocker.
- Support gaps are treated as developer-only problem.

## Decision Rule

Accept beta work only if it improves safe launch, user activation, support diagnosis or evidence for next priorities.

## Complexity Budget

- Build deeply: scope freeze, onboarding, known limitations, support runbook, feedback taxonomy, rollback/pause plan and beta metrics.
- Define lightly: post-beta source roadmap, expansion scoring and future growth experiments.
- Defer: broad public launch, enterprise onboarding automation, source expansion during launch and growth features without beta evidence.
