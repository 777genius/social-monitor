# 282 - DSAR Access/Delete/Portability Workflow

## Decision

Data subject rights are executed through explicit workflows, not manual database scripts.

The platform must support access/export, deletion/erasure, correction and portability where applicable.

## Sources

- ICO right of access: https://ico.org.uk/for-organisations/uk-gdpr-guidance-and-resources/individual-rights/individual-rights/right-of-access/
- ICO right to erasure: https://ico.org.uk/for-organisations/uk-gdpr-guidance-and-resources/individual-rights/individual-rights/right-to-erasure/
- ICO right to data portability: https://ico.org.uk/for-organisations/uk-gdpr-guidance-and-resources/individual-rights/individual-rights/right-to-data-portability/
- California CCPA rights: https://www.oag.ca.gov/privacy/ccpa

## Request Types

Support:

- access/know
- delete/erase
- correct
- export/portability
- restrict processing where applicable
- opt out where applicable

## Workflow Stages

```text
request_received
identity_verified
scope_determined
data_inventory_queried
exceptions_checked
export_or_action_prepared
reviewed
fulfilled
evidence_recorded
closed
```

## Data Inventory Coverage

DSAR workflows must inspect:

- user profile
- tenant memberships
- source bindings created by user
- notification preferences
- audit records
- API keys metadata
- summaries generated by user action
- exports
- support access logs
- analytics identifiers

Social source content may include third-party public data and needs separate policy handling.

## Deletion Semantics

Deletion can mean:

- hard delete
- soft delete
- anonymize
- pseudonymize
- retain under legal/security exception
- delete after retention/legal hold expires

The workflow records which action occurred for each data class.

## Export Format

Exports should be:

- machine-readable
- documented
- scoped
- signed or integrity-checkable where needed
- time-limited download URL

Do not include other tenants' or other users' data.

## Automation Boundary

Use a durable workflow/process manager for DSAR because it may span:

- Postgres
- object storage
- search projections
- analytics warehouse
- backups
- vendor systems
- audit evidence

## Architecture Rule

Rights requests are product workflows with evidence, not one-off support tasks.
