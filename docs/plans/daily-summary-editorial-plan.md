# Daily top-30: editorial plan → article

Status: implementation plan. Base: PR #613 (head ad8b728e187ff601d9a9f6326c1ae4e7e33a105d). Changes only for the new daily top-30 profile.

## Outcome
Choose 1–10 distinct topics from all 1–30 frozen, readable ordinary posts. The first topic is the lead; typically 3–5 topics are detailed and the remainder brief. The writer must report every planned topic with sources belonging to that topic. No quotas, mathematical popularity ranking, or uncited claims. GitHub Trending remains a separate appendix.

## Scope boundaries
Keep current selection, deduplication, native likes/Reddit-score ranking, frozen source/metric bindings, reader post catalog, AI picks, promotion board, Used and sourceMix, old artifacts, public DTO, weekly, legacy/recovery routes unchanged. An unpromotable sealed board still returns unsupported before model generation; handling it is a separate task. No DB migration, new orchestrator, flags, new frontend screen, or fallback to first six after editorial failure.

## Implementation
1. **Freeze input unchanged.** Work only after the existing `dailyGenerationInput` authority has been built. Reuse the exact bounded adapter evidence representation for all 30 selected inputs, with bound feedItemId, storyId, provider, publishedAt, native metric and observedAt. Unknown engagement is null. Popularity is contextual; it is not a universal cross-platform score.
2. **Editor capability and strict response.** Extend the existing model port narrowly (optional for non-daily adapters) and reuse the configured runtime/gateway, purpose, attestation, timeout, retries, error classification and cost reporting. Define a new v1 plan with ordered `topics: {title, why, depth: "detailed" | "brief", feedItemIds}[]`. The first is detailed. Strictly validate 1–10 topics, nonempty text and IDs from the frozen input, and no repeated feedItemId anywhere. Do not attempt semantic verification from an ID check. If editor fails, do not start writer.
3. **Writer projection.** Project the validated plan into the existing model's coverage input, using each topic's first source's existing storyId as its anchor while retaining every source ID. Feed the writer the same 30 input evidence objects, a versioned prompt and the projected plan. Exactly one narrative section and topStory per topic in plan order, with its own citations only. Allow cross-original-cluster citations for sources assigned to the same topic in this profile only; never weaken legacy safeguards. Disable silent fallback/top-up/drop/truncate for this profile. The lead describes its own story, without forcing a synthetic cross-topic conclusion.
4. **Profile-specific limits and presentation.** Update schema, prompt, normalizer and editorial quality checks to support 10 topic sections/topStories, adequate length and explicit coverage. Keep other profiles' current limits. In Flutter remove the secondary section `.take(5)` limit, preserving all ordered topics; test the appendix stays separate.
5. **Private proof and publication.** Persist a versioned `dailyEditorialPlan` object only in private artifact JSON, tied to frozen input identity and editor request/response receipt and writer-plan projection. Keep existing `dailyGenerationInput.sent` evidence and payload receipts. The publication guard reconstructs frozen evidence, validates the saved plan and its source bindings, checks the projected writer plan's trusted hash and narrative topic/citation coverage. Its current evidence hash comparison alone does not verify the full writer payload hash; verify the latter against an actual retained command/attestation if supported rather than claiming unverified security. The new profile must have a valid plan; old profiles must retain compatibility. Public DTO remains unchanged.
6. **Shared budget and existing lifecycle.** Editor + writer + existing repair attempts must fit the job's real timeout and combined model budgets. Track usage of already-dispatched editor calls on writer failure; avoid retrying ambiguously spent requests. A failed plan or article never publishes partially; old publication remains until an atomic replacement.
