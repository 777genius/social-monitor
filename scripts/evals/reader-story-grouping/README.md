## Exact main code chain

1. `libs/summary/adapters/evidence/relevance-reader-summary-evidence.selector.ts`, `RelevanceReaderSummaryEvidenceSelector.select`: rank with `reader_post_promotion`, original ingestion cutoff and period/provider filters; obtain normalized evidence. Upstream text safety uses `READER_SUMMARY_ORIGINAL_SOURCE_TEXT_SAFETY_CAP=256000`. This eval starts at the **already normalized frozen evidence** boundary; it does not rerun ranking, provider collection, safety enrichment, persistence or seven-day publication.
2. `libs/summary/domain/services/story-clustering.service.ts`, `StoryClusteringService.cluster`: deterministic story keys and cross-provider title/topic/facet matches, cluster ranking and cap. `story-ranking-policy.ts` currently exposes `STORY_RANKING_POLICY_V1` with version **story_ranking_v10**, max 200 clusters and 4 selected evidence per cluster. `story-key-normalizer.ts` and `story-cluster-membership.ts` own identity and membership.
3. `relevance-reader-summary-story-relation-decisions.ts`, `verifiedReaderSummaryStoryRelations`: union actual `buildStoryRelationCandidates`, `buildBoundedStrictTitleStoryRelationCandidates` and `promotionSupportCandidates`. Primary retrieval is cross-provider-family, guarded by facets/canonical conflict/time (30 hours), lexical context and similarity; capped at 32 and four per cluster pair. Strict-title recall is an additional bounded lane (eight, one per cluster pair), not the asynchronous shadow result. Promotion support includes existing deterministic clusters and exact-title cross-provider posts; the primary cap is not a cap on the combined union.
4. `libs/summary/adapters/model/agent-runtime-reader-summary-story-relation-verifier.adapter.ts`, `AgentRuntimeReaderSummaryStoryRelationVerifier.verify`: uses the actual instructions, evidence excerpt selection and JSON schema from the sibling `...-prompt.ts`. `normalizeBinaryDecisions` is private, exercised by invoking this adapter. Post text is untrusted data. Source excerpts are at most 4096 UTF-16 units and preview 640. `active-reader-summary-generation-profile.ts` fixes Codex **gpt-5.6-sol/high**, purpose `social_monitor.reader_summary.verify_story_relations.v2`; default max output 6000, timeout 300000ms. Request capture stops at injected `client.runTask`, before any transport/model call.
5. `libs/summary/domain/services/story-relation-decision-trace.ts`, `reconcileStoryRelationDecisions`: validates exact candidate coverage, unknown/duplicate/missing/bad decisions; the whole malformed batch fails closed. A valid true decision requires confidence **>=0.92** (`story-relation-candidates.ts`). Negative and below-threshold decisions are distinct. `reader-summary-execution-attestation.ts` checks execution identity/output. This eval additionally compares the canonical **request** hash, schema and evidence hashes on import.
6. The selector reclusters with approved pairs and strict-title pairs. `belongsToVerifiedStoryCluster` checks compatibility with **every** member in the verified-relation branch, not just any graph neighbor. The deterministic same-key branch has its own facet-conflict rule. Only approved relations whose endpoints actually share an authoritative cluster graduate into promotion. The eval reproduces this small orchestration using the actual functions, without implementing a classifier.
7. `relevance-reader-summary-promotion-candidates.ts`, `promotionPolicySelection`; `reader-summary-editorial-candidate.ts`, `readerSummaryPromotionV2Candidate`; `libs/feed/domain`'s `evaluateReaderPromotionV2` / `rankReaderPromotionV2`: admission and scoring from preserved facts. `reader-summary-editorial-slate.ts`, `composeReaderSummaryEditorialSlate` and `materializeReaderSummaryEditorialSlate`: top eight/additional eight, provider caps, semantic representatives, eligible independent support. `semanticStoryMembership` unions authoritative cluster membership, graduated relations and canonical identity. The evaluation records admission, capacity/duplicate exclusions, pre-promotion clusters and final publication separately.
8. `relevance-reader-summary-related-topics.ts`, `verifiedReaderSummaryRelatedTopics`, calls `buildRelatedTopicCandidates` and `reconcileRelatedTopicVerdicts` after fixing the editorial slate. This is explicit `same_story / related_topic / unrelated`, directed to an official anchor, metadata only and nontransitive. It cannot promote a rejected subject or turn a merely related post into a duplicate. It is distinct also from topic-map layout's `reconcileVerifiedReaderSummaryTopicRelations` (sameTopic, 0.82) in `reader-summary-topic-relation-reconciliation.ts`. Neither related-topic nor topic-map live phases are invoked by this bounded same-story lane.

Thus AI is part of grouping, not its sole authority. Some matching is deterministic; AI only sees retrieved pairs, then confidence, cluster guards and product admission still apply. The prompt allows a same-author series within one provider, but the current provider-family guard exits before that allowance. RSG-044/050 document the real control cases; this task preserves the production rule.

## Evaluation contract and limitations

The reference has 50 labelled pairs in 12 purposive blocks, including ten with 3+ items. Block periods are custom UTC windows spanning the original daily sourceWindows. Request time is the real original ingestion cutoff (`2026-09-05T19:52:42.828Z`), not a rewritten historical observation. IDs use tenant e001/workspace e002 and fixture interest scopes. The block order is frozen and reversed-input grouping is shown separately; it is not the original whole-day feed order. No capacity conclusion about the 3480-post population follows from these small blocks.

`caseRows` separates already-deterministic membership, shortlisted candidates, same-family exclusion, isolated-pair vs block-context retrieval misses, raw normalized decisions, confidence, authoritative relation membership, admission and publication. A context miss is deliberately not asserted to be a specific cap without evidence. Per-provider-pair confusion matrices contain TP/FP/TN/FN, unscored/unavailable counts, precision and recall numerators/denominators. Retrieval recall excludes already-deterministic positives; deterministic coverage has its own denominator. Model semantics are scored only after trusted live import and only for actual returned scored candidates. Publication false negatives include admission/capacity, so publication matrices are not model metrics. There is no overall accuracy.

The first deterministic replay retrieved ten of the 15 scored cross-provider positives, including five already deterministic matches requested again as promotion support; five Fable release positives were missed. No scored negative reached the verifier in these blocks. Accordingly the bounded live phase cannot estimate verifier specificity on hard negatives. Nine requests contain 14 pair decisions: ten scored positives, three ambiguous and one unlabelled contextual edge. All are visible; only the ten scored positives count toward model-semantic denominators. Request identities remain stable even if confidence changes.

42 of 49 unique selected posts lack authoritative engagement in the frozen replay. Other observed rejection reasons include quality/relevance/integrity floors, stale engagement and unresolved regression. One post (the Reddit P(DOOM) announcement) is admitted. These constraints are preserved, not repaired. Publication of all semantically related posts is not a valid completion criterion for this input.

## Live parent phase and trust

See `.cache/real-story-grouping-eval/handoff/OPERATOR.md` for concrete paths, hashes and effect budget. `live.ts` exports `runLiveWithTrustedClient` and supports a parent-reviewed module exporting `createTrustedComposition(): Promise<{client, operatorRecord, close}>`. The client must be the **existing authenticated trusted subscription runtime composition**, scoped to the disposable fixture IDs. The worker supplies no network/auth shim and does not read auth seeds, API keys or service tokens. No worker services or nested agents are launched.

The capture manifest includes the exact command and the actual canonical envelope returned by the pure `admitSubscriptionRuntimeRequest` function in `apps/agent-runtime/src/subscription-runtime-purpose-model-policy.ts`. Calling this pure admission function during materialization does not run a runtime/provisioning check. The existing runtime applies the same purpose/profile policy; parent must confirm the configured adapter options equal the captured defaults. Do not edit prompts, model, provider instance, controls or IDs after inspection.

A live operator writes one receipt per response plus the final aggregate; started markers make interruption visible and the harness will not reuse an existing output directory. It does not retry RPCs. The production runtime's standard retry policy may make an ephemeral fallback attempt: budget up to two launcher attempts per task, with additional provider-internal retries outside this harness's accounting. Never restart a pending RPC merely because observation timed out; inspect the original request in trusted runtime state.

Import:

```sh
TS_NODE_PROJECT=scripts/evals/reader-story-grouping/tsconfig.json node -r ts-node/register/transpile-only -r tsconfig-paths/register scripts/evals/reader-story-grouping/run.ts import .cache/real-story-grouping-eval/live-import /absolute/path/to/receipt.json TRUSTED_RECEIPT_FILE_SHA256
```

Import rematerializes the requests and requires exact source, fixture, schema, request and response identities, native production adapter attestation verification and complete decision reconciliation. Live mode requires the **independently supplied file hash** obtained by the parent from its authenticated capture. JSON attestations/hashes are not signatures and cannot establish who produced a file on their own: authentication relies on that external trusted composition and operator provenance. A self-labelled receipt is not proof of a model invocation. Unknown/altered/missing/duplicate responses fail import. Missing transport, approved disposable scope, runtime health/launcher identity or independently trusted receipt means live stays NOT_RUN. No fabricated receipts are offered as live evidence.
